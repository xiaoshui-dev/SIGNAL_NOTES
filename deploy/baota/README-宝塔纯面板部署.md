# Signal Notes 宝塔纯面板部署教程

这份教程只使用宝塔 Linux 面板，不需要连接 SSH，也不需要打开终端。下面出现的路径、端口和环境变量都是面板字段中要填写的内容，不是命令。

适用部署包：`signal-notes-baota-20260817.zip`

## 一、最终部署结构

部署完成后：

- Nginx 负责介绍页、博客页和后台页面。
- Java 21 负责文章、分类、后台数据和邮件服务。
- MySQL 8 保存文章与站点设置。
- 正式访问地址是你自己的 HTTPS 域名。
- Java 后端只监听服务器本机的 `127.0.0.1:8080`，不会直接暴露到公网。

这套纯面板方案不使用部署包中的 `signal-notes.service`，也不需要手动执行任何数据库、Java 或 Nginx 命令。

## 二、在软件商店安装运行环境

进入宝塔左侧的“软件商店”，依次安装：

| 软件 | 选择建议 |
| --- | --- |
| Nginx | 1.24 或更高版本 |
| MySQL | 已安装的 5.7 可以继续使用；新服务器建议 8.0 |
| Java 项目管理器 | 使用当前最新版 |
| OpenJDK | 在 Java 项目管理器中安装 Java 21 |

如果 Java 项目管理器里没有“环境变量”设置项，先在软件商店中更新 Java 项目管理器。本文不采用命令行补充配置。

## 三、上传并解压部署包

1. 打开宝塔左侧“文件”。
2. 进入 `/www/wwwroot`。
3. 点击“上传”，选择 D 盘中的 `signal-notes-baota-20260817.zip`。
4. 上传完成后，点击压缩包右侧“解压”。
5. 确认解压后的目录名是 `signal-notes`。
6. 最终目录应为 `/www/wwwroot/signal-notes`。

打开该目录，确认至少能看到：

| 目录或文件 | 用途 |
| --- | --- |
| `frontend` | 前端静态页面 |
| `backend/signal-notes-blog.jar` | Java 后端程序 |
| `database/signal_notes.sql` | 当前文章和站点内容 |
| `uploads` | 后台上传图片的保存目录 |
| `README-宝塔部署.md` | 原始部署参考文档 |

在宝塔文件管理器中选中 `uploads` 目录，点击“权限”，把所有者设置为 `www`，用户权限设置为可读、可写、可进入。

然后在宝塔“文件”中进入 `/www/backup`，点击“新建目录”，创建 `signal-notes`。同样把该目录的所有者设置为 `www`，用户权限设置为可读、可写、可进入。这个目录用于保存后台生成的备份。

## 四、创建数据库并导入内容

1. 打开宝塔左侧“数据库”。
2. 点击“添加数据库”。
3. 数据库名填写 `signal_notes`。
4. 用户名填写 `signal_notes`。
5. 密码点击宝塔的“随机”按钮生成强密码，并临时记录下来。
6. 访问权限选择“本地服务器”。
7. 字符集选择 `utf8mb4`；如果面板没有这一项，使用默认的 UTF-8 设置。
8. 保存数据库。
9. 在数据库列表中找到 `signal_notes`，点击右侧“导入”。
10. 根据服务器版本选择 SQL：MySQL 5.7 上传 D 盘中的 `signal_notes_mysql57.sql`；MySQL 8.0 上传部署包中的 `database/signal_notes.sql`。
11. 上传后选中该 SQL 文件，再点击“导入”。
12. 等待面板显示导入成功。

### MySQL 5.7 第一次导入已经报错时

报错中的 `Unknown collation: utf8mb4_0900_ai_ci` 表示导入被 MySQL 8 专属排序规则中断。后面的 `flyway_schema_history` 不存在只是连锁错误，不需要逐条处理。

如果 `signal_notes` 是本次部署刚创建的新数据库，并且里面没有需要保留的数据，请在宝塔“数据库”页面删除这个导入失败的数据库，再按本节前面的步骤重新创建。重新创建时可以继续使用原密码；如果换了密码，Java 项目环境变量中的 `DB_PASSWORD` 也要同步修改。

重新进入“导入”，这次只上传并导入 D 盘中的 `signal_notes_mysql57.sql`，不要再次选择原始的 `signal_notes.sql`。导入过程不再出现红色错误信息才算成功。

导入内容包括当前文章《开端》、分类“自言自语”、标签、站点文案和分享设置。SMTP 密码、原后台账号、联系表单、订阅记录和审计日志已经移除，避免把本地隐私数据上传到服务器。

## 五、在面板中添加 Java 后端

1. 打开“软件商店”，进入已经安装的“Java 项目管理器”。
2. 点击“添加项目”或“添加 Java 项目”。
3. 按下面的表格填写。

| 面板字段 | 填写内容 |
| --- | --- |
| 项目名称 | `Signal Notes` |
| 项目类型 | `Spring Boot` 或 `Jar 项目` |
| 项目 JDK | `Java 21` |
| 项目文件 | `/www/wwwroot/signal-notes/backend/signal-notes-blog.jar` |
| 项目目录 | `/www/wwwroot/signal-notes/backend` |
| 项目端口 | `8080` |
| 运行用户 | `www` |
| 开机启动 | 开启 |
| 守护运行 | 开启 |
| 绑定域名 | 暂时不绑定 |

如果面板提供“JVM 参数”，填写：`-Xms256m -Xmx768m -Dfile.encoding=UTF-8 -Duser.timezone=Asia/Shanghai`。

先不要点击启动，继续配置环境变量。

## 六、填写 Java 项目的环境变量

在 Java 项目管理器中打开 `Signal Notes` 的“设置”，找到“环境变量”。不同版本可能叫“项目变量”或“Environment”。逐项添加：

| 变量名 | 变量值 |
| --- | --- |
| `SERVER_ADDRESS` | `127.0.0.1` |
| `SERVER_PORT` | `8080` |
| `DB_HOST` | `127.0.0.1` |
| `DB_PORT` | `3306` |
| `DB_NAME` | `signal_notes` |
| `DB_USERNAME` | `signal_notes` |
| `DB_PASSWORD` | 第四步中由宝塔生成的数据库密码 |
| `ADMIN_USERNAME` | 你准备使用的后台登录名，例如 `admin` |
| `ADMIN_PASSWORD` | 自己生成的至少 12 位强密码 |
| `APP_PUBLIC_URL` | 正式地址，例如 `https://blog.example.com` |
| `CORS_ORIGINS` | 与 `APP_PUBLIC_URL` 完全相同 |
| `UPLOAD_DIR` | `/www/wwwroot/signal-notes/uploads` |
| `BACKUP_DIR` | `/www/backup/signal-notes` |

填写时注意：

- `APP_PUBLIC_URL` 和 `CORS_ORIGINS` 末尾都不要加 `/`。
- 不要继续使用本地演示密码。
- 环境变量名称必须全部使用大写。
- 数据库密码不要填成教程中的示例文字。

保存环境变量后，回到项目列表，点击“启动”。项目状态应变成“运行中”。

如果状态很快又变成“停止”，点击项目右侧“日志”，重点检查数据库密码、Java 版本和端口占用提示。所有排查都可以在面板日志中完成。

## 七、创建前端网站

1. 打开宝塔左侧“网站”。
2. 点击“添加站点”。
3. 域名填写你的正式域名，例如 `blog.example.com`。
4. 根目录填写 `/www/wwwroot/signal-notes/frontend`。
5. PHP 版本选择“纯静态”。
6. 数据库选择“不创建”，因为数据库已经在第四步创建。
7. 保存站点。

打开站点的“网站目录”，确认运行目录就是 `/www/wwwroot/signal-notes/frontend`，不要选到项目根目录，也不要选到 `backend`。

## 八、在面板中设置 Vue 路由回退

博客使用前端路由。如果不设置回退，直接打开文章、分类或后台地址时可能出现 404。

1. 打开“网站”。
2. 点击该域名右侧“设置”。
3. 进入“伪静态”或“URL 重写”。
4. 如果模板列表中有 `Vue`、`Vue Router` 或 `History`，直接选择该模板并保存。
5. 如果没有现成模板，选择“自定义”，在面板编辑框中填写 `try_files $uri $uri/ /index.html;`，然后保存。

这一步仍然是在宝塔面板中完成，不需要终端。保存后分别在浏览器中打开首页、`/blog` 和 `/admin`，三个页面都应正常显示。

## 九、在面板中添加 API 反向代理

前端和后端使用同一个域名，需要在站点设置中添加两条按路径生效的反向代理。

打开“网站” → 选择域名右侧“设置” → “反向代理”，然后添加第一条：

| 面板字段 | 填写内容 |
| --- | --- |
| 代理名称 | `signal-notes-api` |
| 代理目录或匹配路径 | `/api/` |
| 目标 URL | `http://127.0.0.1:8080` |
| 发送域名 | `$host` 或“保持原域名” |
| 缓存 | 关闭 |
| WebSocket | 关闭 |

再添加第二条：

| 面板字段 | 填写内容 |
| --- | --- |
| 代理名称 | `signal-notes-uploads` |
| 代理目录或匹配路径 | `/uploads/` |
| 目标 URL | `http://127.0.0.1:8080` |
| 发送域名 | `$host` 或“保持原域名” |
| 缓存 | 开启或保持默认 |
| WebSocket | 关闭 |

保存后不要创建整站代理。整站代理会让 Nginx 不再直接提供 `frontend` 中的静态文件。

如果你的反向代理窗口没有“代理目录”或“匹配路径”字段，先更新宝塔面板和 Nginx 管理组件，再重新打开站点设置。不要把整个域名绑定到 Java 项目上。

## 十、申请并开启 HTTPS

1. 打开“网站” → 域名右侧“设置” → “SSL”。
2. 选择“Let's Encrypt”。
3. 勾选当前域名。
4. 点击“申请”。
5. 申请成功后开启“强制 HTTPS”。
6. 回到 Java 项目管理器，检查 `APP_PUBLIC_URL` 和 `CORS_ORIGINS` 都已经填写成 `https://` 地址。
7. 如果刚刚修改了环境变量，在项目列表点击“重启”。

如果证书申请失败，先检查域名是否已经解析到当前服务器，以及宝塔“安全”页面是否放行了 80 和 443 端口。

## 十一、首次上线验收

在浏览器中逐项检查：

| 地址或操作 | 正确结果 |
| --- | --- |
| 正式域名首页 | 显示科技风格介绍页 |
| `/blog` | 显示博客列表和《开端》 |
| `/blog/categories/monologue` | 显示“自言自语”分类和《开端》 |
| `/admin` | 显示空白的生产登录表单，不展示演示密码 |
| 使用生产管理员登录 | 能进入后台首页 |
| 新建并发布文章 | 博客列表和对应分类立即显示文章 |
| 后台上传图片 | 图片可预览，文章页能够显示 |
| 生成分享图片 | 二维码指向正式 HTTPS 域名 |

进入后台“设置”后，重新填写 SMTP 主机、端口、邮箱账号和授权码，再使用“发送测试邮件”按钮验证。部署包没有携带本地 SMTP 密码，这是有意的安全处理。

## 十二、完全使用面板排查问题

### Java 项目无法启动

进入“Java 项目管理器” → `Signal Notes` → “日志”。

- 出现数据库连接失败：重新检查 `DB_NAME`、`DB_USERNAME` 和 `DB_PASSWORD`。
- 出现 Java 版本错误：把项目 JDK 改成 Java 21。
- 出现端口占用：确认其他 Java 项目没有使用 8080。
- 出现目录不可写：在“文件”中把 `uploads` 所有者改为 `www`。

### 首页能打开，但文章不显示

1. 在 Java 项目管理器确认项目状态是“运行中”。
2. 在网站“反向代理”确认 `/api/` 已启用。
3. 在“数据库”中确认 `signal_notes` 的 SQL 显示导入成功。
4. 在浏览器直接打开正式域名后的 `/api/posts`，正常时会看到文章数据。

### 刷新文章页或后台后出现 404

进入网站“伪静态”或“URL 重写”，重新确认已经选择 Vue/History 模板，或自定义回退内容已经保存。

### 后台登录失败

1. 确认使用的是 Java 项目环境变量中的 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD`。
2. 环境变量修改后必须在 Java 项目列表点击“重启”。
3. 不要使用开发环境中的演示密码。

### 上传成功但图片打不开

1. 在“文件”中检查 `/www/wwwroot/signal-notes/uploads` 是否存在。
2. 把目录所有者设为 `www`，并给所有者读写权限。
3. 在站点“反向代理”中确认 `/uploads/` 规则已启用。

### 测试邮件发送失败

1. 在后台“设置”确认 SMTP 已启用。
2. 465 端口使用邮箱授权码，不使用邮箱网页登录密码。
3. 确认发件人邮箱与 SMTP 用户名符合邮箱服务商要求。
4. 保存设置后再点击测试发送，等待结果提示，不要重复连续点击。

## 十三、面板内备份与更新

### 备份

1. 在“数据库”中找到 `signal_notes`，点击“备份”。
2. 在“文件”中打包下载 `/www/wwwroot/signal-notes/uploads`。
3. 在宝塔“计划任务”中分别创建数据库备份和目录备份任务。
4. 建议保留 7 份日备份和 4 份周备份。

### 更新

1. 先在“数据库”和“文件”中完成备份。
2. 在 Java 项目管理器中停止 `Signal Notes`。
3. 在“文件”中替换 `backend/signal-notes-blog.jar`。
4. 替换 `frontend` 目录中的生产文件。
5. 不要覆盖服务器上的 `uploads`。
6. 回到 Java 项目管理器启动项目。
7. 在网站设置中确认反向代理和 SSL 仍然开启。
8. 使用浏览器重新完成第十一节的验收。

至此，整个部署、排查、备份和更新流程都可以在宝塔面板内完成。
